# Common schema

<p><img src="<!--path pict-->md2html_schema.png" title="md2html" class="floatRight light_only" /></p>

**M<sub>2</sub>H** accepts the following artifacts as its input:

- source Markdown texts;
- one or several HTML templates;
- one argument file;
- HTML page resources.

The program processes these artifacts and generates a set of static HTML pages that may 
represent a logically related documentation with a sidebar menu, navigation, index and 
other elements.

The following subsections describe the above artifacts in more details.

<p style="clear: both;"></p>


## Source Markdown texts

These texts comprise the main documentation content written by the author. They are written in 
the Markdown language [<!--ref markdown-->]. The 
[Page content section](<!--page page_content-->) describes the methods, tricks and elements that
may be used in process of the content writing.


## HTML templates

An HTML artifact that is generated out of a markdown text is not a complete HTML page. It's
just a fragment that must be put inside the `<body>...</body>` HTML element. A **template** may
be considered as an HTML page that doesn't have the main content but just specifies the place
(placeholder) where this main content must be inserted.

See [here](<!--page templates-->) for more details about templates and other placeholders that 
may be used in templates.


## Argument file

The *argument file* defines the set of input source files and different parameters for the 
following HTML documents generation. See [here](<!--page usage-->#using_argument_file) 
for more details.


## HTML page resources

Different resources, like CSS, JavaScript and images are not processed by the program. The program
may just adjust the location of these resources while putting link on them into the certain pages. 
These are usually [plugins](<!--page plugins-->) that perform these adjustments.

# Restrictions and security

**M<sub>2</sub>H** is a static site generator that means that every output HTML page contains
everything required for display, including such repeated elements like menus and sidebars.
There's no server that could generate these elements on the fly.
This approach speeds up navigation and even for pretty large and complex sites must not be a
significant overhead. But if the site is very huge, its full regeneration may be long enough
(like 5 sec or so). Also, e.g., [index plugin](<!--page plugins-->#index_plugin) doesn't have
pagination, and with enormous number of terms the index page may become pretty heavy.
So if the writing project becomes too large it may be good to consider splitting it into several
projects.

**M<sub>2</sub>H** doesn't restrict HTML code inside the Markdown texts. Particularly, these texts 
may contain JavaScript that will be translated unchanged into the generated HTML page. This
must not be a problem for personal use but may be a security issue when converting and
publishing source texts from untrusted third-parties. Click the image below to see how it may
look like.

# History

**M<sub>2</sub>H** was born in about 2019 as a Python script of about 50 lines of code written
in about one hour. It was used for writing notes on a computer science study course.
Then this solution was used for the other writing works and, as the requirements grew, it developed
up to the current state.

<!--index ["Java implementation"]-->
As for the Java implementation, it appeared as a response to the lack of Python in an environment
where the program was going to be used. For now the Java implementation slows down the development
as it needs writing the same things in two languages. Anyway it's going to be supported as it
gives additional level of platform independence 🙂

# Alternative solution

There's **Pelican** [<!--ref pelican-->] static site generator that may be considered quite close
to **M<sub>2</sub>H** by its functionality. It looks mature and feature-rich enough, and has a
similar motivation, see
[Some history about Pelican](https://docs.getpelican.com/en/stable/report.html). 

Pelican is written in Python only, uses the same Python-Markdown module [<!--ref py_markdown-->] and 
also supports another mark up language ---
[reStructuredText](https://docutils.sourceforge.io/rst.html).

The main difference may be described the following way:

- Pelican --- initially designed for keeping blogs, may be used for the other kinds of writing
    projects
- M<sub>2</sub>H --- initially designed for keeping study notes, does not have specific blogging
    features
